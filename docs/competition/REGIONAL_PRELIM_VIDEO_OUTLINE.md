# 知事 RuleFlow 区域初赛介绍视频制作方案

版本：0.1｜日期：2026-11-04｜当前状态：制作方案与讲解初稿已建立，尚未录制、剪辑或生成成片。

**视频是团队计划实际提交的初赛成果。**官方通知将初赛视频列为可选，但团队已决定与项目计划书、Beta＋源代码一起提交，不将其降为备用任务。当前没有找到视频专用模板，也未在本地通知/附件中发现时长、画幅、分辨率、文件大小、容器/编码的硬性限制；这些须由 A 在正式录制规范确认前核对提交平台或更新通知。初赛评分未单列可选视频加分，不承诺“提交必加多少分”。依据见[团队执行计划第 8 节](../plans/TEAM_EXECUTION_PLAN.md#8-官方要求及团队初赛三项交付)。

## 1. 要让评委看明白什么

选取一项来源与原模板版本清楚的校园申请，展示手机用户怎样从外部收到信息，逐步核对条件、准备材料和填写表格，再安排执行并反馈进度。具体场景由 RF-004 确认；奖学金仅是候选，不先假定原表是 DOCX。

视频需要回答六个具体问题：

1. 用户原来在哪些地方需要重复查看、输入和安排？问题依据来自真实观察，未验证的仅作场景说明。
2. 外部分享进入知事后如何继续办理？展示 Android 操作与实际状态衔接。
3. AI 给出什么建议，依据在哪里？展示原文、字段来源、UNKNOWN 和人工修正，而非只给一段看似正确的答案。
4. 资料如何用于条件/材料核对和申请表？展示授权、复用、缺失提示及可编辑输出。
5. 办理怎样进入日程，用户能否改动？展示课程冲突、确认、反馈和调整；未实现增强明确分开。
6. 相比一次问答，这套流程增加了什么可验证结果？展示事项状态、文件产物和行动记录，不泛称所有聊天助手都没有这些能力。

技术说明聚焦“模型建议＋确定性校验＋用户确认”。Rule AST、三值逻辑和 DAG 是现有基础，不宣传为新发明；多候选/填表/排程增强在实际验收前只能称计划。

## 2. 场景和录制版本

首选一条完整事务，避免每个模块使用互不相关的样例而假装已经联通。通知和表格来自真实原件；演示中的学生资料、经历、文件内容采用可说明且获准使用的去标识或合成数据。需遮去来源中的学校标识，同时保留内部真实来源记录。历史通知标注“历史通知场景复演”，合成数据标注“演示资料为合成数据”。

正式素材来自 BT-01 确认范围内、对应模块验收通过的集成版本，至少登记源码 commit、APK hash、后端版本、设备/系统、样本代号。换版本后重录受影响片段并更新记录。可提前录设备取景样片，不作为功能完成证据。

若某步骤未实现：继续修复/调整 Beta 范围并如实说明，不用静态画面或 Mock 回包替代该步骤。可以保留单独标为“后续规划”的短图示，但不能算作真实演示，也不能用它宣称整条链已完成。Offline Demo 如出现必须明确其性质。

## 3. 分镜与讲解初稿

**内部建议先按约 4 分钟编排**，仅为控制信息量的制作方案，不是官方时长要求。表中时间可按平台限制和实际操作调整；不承诺尚未实现的功能一定进入初赛成片。正式录制前将每行标为“可录 / 待验收 / 本版不展示”，A 与模块负责人共同确认。

| 镜号/建议区间 | 画面和操作 | 讲解要点草稿 | 素材主责 | 可录条件及真实性边界 |
|---|---|---|---|---|
| S01 0:00–0:20 | 项目标识；手机中的通知、原申请表和课程安排，突出同一事务 | “收到一则申请通知后，学生还需要核对条件、准备材料、填写表格并安排办理。知事希望把这些动作连起来。” | A 内容；C/B/D 给受控样本 | 场景已核实；不说未测的节时率/覆盖人数 |
| S02 0:20–0:45 | 从外部应用系统分享通知/附件进入 Android App；展示用户确认 | “信息从系统分享进入知事。是否上传和继续分析，由用户确认。” | A 录整体操作，C 提业务素材 | RF-006、013 等对应路径验收；显示真实外部入口，去掉账号/学校等身份信息 |
| S03 0:45–1:10 | 原文与引用；候选事项确认/关联；一条未知资格及补充/核对 | “AI 提出候选理解，系统保留原文依据。信息不足时显示待核对，用户决定是否创建事项。” | C | 多候选/确认实际通过才录该画面；若本版仍单事项，改脚本准确称单事项，不冒充新流程 |
| S04 1:10–1:30 | 材料要求、已有文件关联和缺项；跳转真实表模板 | “材料不仅要找到，还要确认是否适用。缺什么、用哪份文件，都能核对。” | C 主录，B 提文件/资料接口结果 | 不能把同名文件命中展示成适用性已验证；保留缺项或待确认状态 |
| S05 1:30–2:10 | 基本资料/经历授权；字段匹配；缺失/歧义；编辑一处理由或字段；确认、导出并用外部应用继续编辑 | “已确认资料供本次填写复用。建议可以修改，确认后才写入副本，原表保留。这里展示的是这一份已验证模板。” | B；A 验手机交付 | RF-005→对应完整填表与 049 验收；真实显示格式，第二格式没验不得宣称全支持 |
| S06 2:10–2:45 | 清单任务进入日程，结合课表显示冲突；选择/修改草案后确认 | “清单连接到时间安排。建议需要满足课程和任务约束，用户确认后才进入正式日程。” | D 主录，C 清单衔接 | 约束和提交验收；多方案/固定/局部重算仅实际通过时展示，否则保留真实已验范围 |
| S07 2:45–3:10 | 一条真实提醒；用户确认完成/改期；查看状态与调整原因 | “执行过程中，用户记录进度或改期。系统说明受影响安排，再由用户确认。” | D；A 真机组织 | 提醒实触发/取消记录；等待可明确标快进，不能伪造即刻触发。若仅手动调整，说明手动，不称自动重算 |
| S08 3:10–3:40 | 简单数据流图加上述画面的证据定位，说明 AI/规则/写回/排程各职责 | “模型负责理解与建议，规则和业务逻辑负责校验，关键动作由用户确认。证据、版本和状态将操作连接起来。” | A 汇总，B/C/D 核技术 | 架构图区分现有与计划，规则来源不能错配；不展示密钥、真实日志和敏感文件路径 |
| S09 3:40–4:00 | 同一事务的实际产物和状态；已验证范围、已知限制、下一步各一句 | “这一版本已验证的范围是……，未覆盖的是……。后续依据真实模板和使用反馈逐步扩展。” | A 统稿，全员确认 | 留白按实际发布清单填写；若无用户实验结果不写百分比或广泛好评 |

这是一份待真实验收结果补全的讲解稿，不能直接把条件句删掉作为完成宣传。最终成片应让主要业务画面有足够阅读时间，完整闭环优先于功能列表。必要时缩短片头和技术讲解，不能用极快切换掩盖错误和确认步骤。

## 4. 素材责任与交付规范

| 人员 | 必须提供的素材 | 同时附带的技术核验 |
|---|---|---|
| A | 场景说明、整体 Android 操作、跨模块入口与集成结果、架构/价值表达、素材目录 | 每段对应版本和验收记录、全链是否真正联通、当前/计划描述一致 |
| B | 资料/经历复用、字段来源、人工编辑、草稿确认、真实格式写回、Android 保存/打开/分享 | 模板版本/hash、原件和输出、导出可编辑/版式结果；AI 建议和用户填写区分 |
| C | 导入、来源引用、事项确认、资格 UNKNOWN、材料适用/缺项和办理清单 | 原通知版本、规则及证据对应、错误/未知处理；候选/Case 已实现边界 |
| D | 课表、任务选择、约束/候选/草案、用户确认、提醒/完成/调整 | 课表样本、约束预期/实际、提醒设备与触发/取消、正式日程状态 |
| 实际视频制作人员 | 剪辑工程、配音、字幕、可审初剪、修订版、最终成片 | **负责人待单独安排**；提供制作源文件、素材/音乐授权和导出参数，不自动归 A/B/C/D 任一人 |

各人优先提供可直接剪辑的短片及一段连续无剪辑操作证据，避免只交零散截图。内部建议统一竖屏操作画面、清晰文字和一致字体/字幕风格；最终画幅和编码以平台核对结果为准，不为后期效果重新设计产品。

每个素材附一条轻量记录，可直接引用任务/PR 证据，不另写重复报告：

```text
素材编号 / 模块 / 录制者 / 日期
对应 RF、验收记录、源码 commit、APK hash、后端版本
设备/系统、样本代号、真实/合成/历史复演标识
展示了什么；不能证明什么；是否含联网模型及等待
原始素材位置、剪辑建议、拟用讲解、需遮挡项
模块核对者及本版可使用状态
```

隐私原件和真实个人资料使用受控存储，不上传到公共 Git 或共享演示包。各模块自行先审；A 再审完整叙事和匿名。音乐/字体/图片使用可确认授权的资源；无需装饰素材时可用直接操作＋字幕，避免新增版权和制作负担。

## 6. 与开发阶段衔接

- **最小准备阶段：**V-00/01/02 启动，核对平台、样本和录制设备；B/C/D 将可演示条件写入模块验收。用户观察此时开始，不能等成片时补造故事。
- **并行开发阶段：**通过一个切片就保存对应证据与可用短片；先录稳定入口，暂未稳定的页面不反复精剪。A 维护镜号状态。
- **滚动集成阶段：**用同一集成版本补连续场景，定讲解与技术图。核对跨模块数据确实衔接后再采用“完整流程”的表述。
- **12-15 内部检查点：**争取脚本、验收过的核心素材齐备；落实制作人后形成可审初剪。未达到时登记具体缺镜/原因和容量调整，不冒充已有成片。
- **初赛提交前：**完成修订、V-08/09/10 和三项一致性检查，留出一次实际修正与重传。正式截止为 **2027-01-15 18:00**，内部冻结/上传日期由 A 按实际交付进展协调，不等当天第一次制作或上传。

全片初剪前可先剪一个已验镜头核对风格和可读性；镜头时长、旁白及图示依实际结果调整。制作人员改变不改变 B/C/D 的业务主责。
