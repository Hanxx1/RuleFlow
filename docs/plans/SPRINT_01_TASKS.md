### RF-001 工程走读、接口样例和基础协作

- **主责/协作：**A 组织；B/C/D 各提交自己业务的一条走读结果。A 验完整性，相关成员互审。

- **目标：**每人知道数据从哪个页面到哪个 API/服务/测试，能够独立运行基本 Web/后端，知道何时请求公共评审。
- **步骤：**①确认本机工具链和实际影响任务的环境阻塞；②按 README 在个人工作区配置并运行基本入口，不复制真实数据库；③B 追资料→原件，C 追导入→Review，D 追 Task→草案；④用合成样例写成功、UNKNOWN、stale、拒权/取消、错误响应；⑤约定分支、公共文件占用、PR 和证据记录方式。

- **公共接口：**owner、revision、consent、request_id、错误包络；兼容现有字符串错误，不宣称全部统一。
- **验收：**四人各能说明一条请求链并提供实际启动结果或准确环境阻塞；样例有输入/输出/异常，不把 Mock 当实测。
- **测试/证据：**启动命令/安全日志、版本、样例和走读路径；无需为走读跑全部测试。
- **技术说明：**一页“我负责的入口/函数/消费者/未知项”，放任务记录即可；A 汇总协作规则，不另建重复系统。

### RF-004 真实通知与原始申请表核实

- **主责/协作：**B；A 协助收集，C 确认通知及附件来源关系；B 提交，A 复核清单。
- **依据：**指导第 5 节；`server/app/parsing.py::parse_bytes`、`services/file_validation.py`。
- **目标：**确定一份可合法使用、来源清楚、确切版本的代表模板，查明原始格式和提交条件。
- **步骤：**①取得通知正文和直接附件；②记录来源、取得时间、申报类别、版本/hash、DOCX/XLSX/XLS/PDF 实际类型；③人工标出可填字段、审核/签字区、长理由和字数；④准备虚构但标注为合成的填充值及人工预期；⑤记录 Word/WPS/Excel 可用环境。

- **公共接口：**向 C 提模板与通知/类别关联，向 028 提模板 hash/格式/禁止区；不预先固定所有 locator 数据结构。
- **验收：**能打开原件、说明来源/版本/提交格式；没有假定国家奖学金表必为 DOCX；保留原件，不偷偷转换后宣称原格式支持。
- **测试/证据：**来源登记、原件 hash、结构截图、受控样本位置和期望填写表；原始实名数据不提交公开仓库。
- **技术说明：**“模板能力/难点/保护区域/首轮格式理由”，供 005、计划书和视频引用。
- **风险/阻塞：**缺原附件、历史版本、材料授权和提交格式不明；先标受阻，再补样本。

### RF-005 单模板最小保真写入实验

- **主责/协作：**B 实施，A 人工检查编辑/版式；仍由 B 负责后续完整填表模块。
- **依据：**004 原件；`parsing.py` 的 python-docx/openpyxl/xlrd 读取基础，已有 parser 不提供完整写入契约。
- **目标：**尽早发现格式写回风险，不先做 AI、数据库、前端或万能适配器。
- **步骤：**①复制受控样本到隔离实验位置、计算原件 hash；②人工映射少量字段；③写姓名、前导零编号、空值、特殊字符和模板要求长度的理由；④另存、程序复读；⑤在适用 Office/WPS 查看、继续编辑及打印/分页检查；⑥记录保真边界及后续最小适配器要求。
- **依赖/立即性：**依赖 004；没有样本时可阅读定位/列测试，不能进入真实写回验收。
- **公共接口：**向 028 提格式位置/能力声明、向 031/035 提确认值→适配器边界；不改旧 parse_bytes 返回。
- **验收：**原件不变，值准确、禁填区不变、导出可继续编辑；DOCX 检查合并/分页，XLSX 检查公式/合并/打印/前导零；超长不可静默截断。失败也必须可复现且说明原因，不计产品功能通过。
- **测试/证据：**脚本/命令、依赖版本、原件/输出 hash、复读值、编辑/版式截图、成功和失败样例。
- **技术说明：**适配范围、损失、下一步需新增什么、尚不能保证什么；仅一模板成功不等于支持全部格式。
- **风险/阻塞：**真实格式为 XLS/PDF 时先验证实际路径，不强制转换 DOCX；提交方不接受转换则不能以转换输出作为闭环完成。
