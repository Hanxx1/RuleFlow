# 知事 RuleFlow 团队执行计划

版本：1.0｜日期：2026-11-04｜用途：内部协作、阶段验收与区域初赛交付。

**主要分工已经确定：A 统筹与集成验收，B 个人资料与智能填表，C 通知理解与事项办理，D 个人日程与智能排程；A、B 共同牵头公共技术。**本文落实责任和执行顺序，不重新分配三个业务模块。阶段目标不代表个人已承诺工时或所有功能的完成日期；按任务成果和技术阻塞调整推进，不以固定工时或 Codex 额度登记作为开工前置。

配套文档：[第一批任务](SPRINT_01_TASKS.md)、[初赛计划书草稿](../competition/REGIONAL_PRELIM_PROJECT_PLAN_DRAFT.md)、[视频制作方案](../competition/REGIONAL_PRELIM_VIDEO_OUTLINE.md)。产品依据为[持续开发指导](../development/NEXT_PHASE_DEVELOPMENT_GUIDE.md)，任务编号与验收细节沿用[57 项工作量评估](DEVELOPMENT_WORKLOAD_ASSESSMENT.md)。本文只补责任、批次和交付，不复制另一份任务评估。

## 1. 执行目标与边界

围绕一个真实校园事务，逐步完成“通知及附件获取→理解候选事项→用户确认创建或关联→资格核对→材料准备→按需填表→清单与时间安排→提醒、反馈及调整”。同时保留独立填表、资料经历、材料库、知识库、清单、日程和课表入口。

三名主力均负责自己业务的前后端、必要平台接入、测试、修复和技术说明。Codex 用于辅助实现，负责人须理解并审查结果。A 对协调和交付质量负责，不代写三个模块，也不接手所有模块测试和修复。

约六周推进窗口仍参考 **2026-11-03 至 2026-12-15**；本计划写于 11 月 4 日，不据此认定团队已于前一天完成任何任务。希望窗口内形成可演示的集成版本及材料初稿。**初赛正式截止为 2027-01-15 18:00**，中间用于考试缓冲、修复、试用、视频与提交版完善。57 项是持续任务池，未进入阶段的既定需求继续保留。

本阶段不新增电脑端、多端同步、后台自动重排、自动登录学校系统或自动提交申请。DOCX、XLSX 写入均为既定目标，先用一种真实原始模板贯通，另一种按验证和容量继续实现；不能将“能读取文件”写成“已支持填写导出”。

## 4. 公共技术先后关系

### 4.1 编码前先确定的契约

| 契约 | 提案/共同确认 | 最少需要明确 | 阻塞范围 |
|---|---|---|---|
| 来源→候选→Case/Evidence | C 提案，D/B 复核，A 协调（002） | 创建前 line/source 引用、候选 revision、确认后 EvidenceRef、多对多原件、旧 case_id、幂等/越权/stale | 阻塞候选存储与确认；不阻塞模板写回实验 |
| Task→Schedule→提醒 | D 与 C 共拟，A/B 审（003） | 独立 Task 来源、Case 可空、通知 Review 门禁、done/skipped、分段完成、删除、时区与版本 | 阻塞独立 Task 迁移/状态联动；不阻塞算法样例整理 |
| 资料/经历/草稿 | B 提案，C/D 消费方确认（012） | 本机/服务器位置、退出/备份、有效资料读取、用途授权快照、历史确认版本 | 阻塞正式存储扩展；不阻塞手填值写入实验 |
| 文件与格式 | B 提字段/locator/导出快照，C 提引用服务，A 审原生结果 | `{kind,id}`、owner、原件 hash、格式能力、删除保护、真实 MIME、取消/拒权/失败 | 阻塞正式填表/文件交付；不需要先统一物理存储 |
| AI 公共调用 | C 首个实现提案，B 对齐各能力，A 审预算 | capability/schema_version、最小输入、引用校验、重试总额、幂等、失效、usage 未知 | 阻塞新 AI 在线能力；确定性匹配、排程/写入继续开发 |

具体新 URL、Schema 和迁移编号经上述评审确定；推荐字段不是已实现接口。以一份样例和决策表达成一致即可，不引入复杂审批层级。

### 4.2 先做可行性验证

RF-004/005 验真实原模板；RF-006 验当前 APK 和已有接收链；RF-007 验合成文件及单条提醒；RF-043 首批只整理约束边界与预期。实验失败也是有效产出，但只记“验证已完成、能力未通过”，不将相关产品能力标已完成。

### 4.3 随功能实施的公共代码

Provider 扩展、调用幂等/预算、文件引用、必要迁移、公共类型/路由、原生桥和部署增强均随实际消费者增量完成。C/D 可以在业务 PR 中实现公共变更并提供回归，A/B 负责协调和审查；禁止另建各自 AI 服务、用户资料库、任务表或重复文件存储。不先拆完整个 main.py，不换 ORM/队列平台来“准备并行”。

## 6. Android 实施边界

源码基线 `c589990` 中，Capacitor 6 的实际原生工程位于 `mobile/android`。已有 `ShareReceiverActivity` 通过 ContentResolver 读取内容 URI、`PendingImportStore` 保留私有队列、`PendingImportsPlugin` 和 `core/native/share.ts` 传递并清理已处理快照。Manifest 有 FileProvider，主 Activity 注册了 PendingImports。`mobile/package.json` 的现有原生依赖包含 Preferences，未见完整的文件输出或本地通知插件；现有 Blob 下载链接不能证明 Android 保存成功。

因此：分享接收优先复用；文件输出/提醒已有插件是否足够，结论是**当前声明的依赖不足以证明完整能力，必须做 007 验证**。本计划不安装插件，不提前指定未经验证的包版本。确需新增时，比较兼容 Capacitor 6 的成熟插件与现有 FileProvider 上的最小桥，记录必要性、权限和错误语义后选择；无需新原生框架。

## 7. Git、Codex 与完成标准

沿用 [AGENTS](../../AGENTS.md) 和[协作规则](../development/CONTRIBUTING.md)中的工程约束；旧文档的横向岗位建议不覆盖本次正式业务分工。

3. 提供方提出接口，消费方确认请求/响应/空值/错误/版本/授权/幂等；样例先行，允许 Mock 开发，不以 Mock 通过替代联调。

5. 改动人读 diff 并自测，相关人员评审后合并。C 改公共 AI 可由 B 审，D 改 Task 由 C 审业务兼容并由 A/B 协调迁移；不要求等 A/B 代写。A/B 忙时可评审其他独立任务，但高风险未定契约不能跳过。
6. 每批合并检查主要真实链路与 Offline Demo；失败先定位和修复，不通过删断言/掩盖错误取绿灯。涉及 Rule/DAG/parser/share 跑相应测试，UI 状态增加必要测试；集成批次按 CI 要求检查。

统一任务状态：**待开始→进行中→待评审→待验收→已完成**，另设“受阻”。受阻记录缺什么、谁协调、下一步；状态改变由实际结果驱动。实验失败可完成“验证任务”，产品卡保持未通过/受阻。

任务完成必须同时具备：需求/接口一致；可实际操作；必要测试与异常恢复通过；相关旧功能回归；权限/版本/幂等符合约定；原生任务有设备证据；PR/版本可追溯；技术说明和已知限制已交。未验设备、未测模型、未覆盖模板必须明确记录；“Codex 生成了代码”不进入已完成。
