# RF-038/039 独立任务依据读取评审

2026-11-23，主线基线 `37a9d62`。本文记录 B 已支持的读取语义、旧 Case 兼容要求和对应验收条件。下表中的任务与依据均为举例，验收结果需由实现后的测试给出。

## 按任务解析依据

旧 Case 页面通过 `GET /cases/{case_id}/resources` 取得依据，按 `evidence_ids` 回查原句。独立任务没有 Case 路径。独立任务读取须满足以下验收条件。服务端应先核对当前账户有权访问该任务，再对任务引用的每条依据核对账户和任务归属。即使同属一个账户，任务乙也不能凭任务甲的 Evidence ID 读出内容。

读取方需要稳定的依据 ID、Case 或独立任务作用域，以及二者中唯一的归属 ID。来源区分通知原文、用户填写和无法溯源的旧记录。展示沿用 `source_name`、`text`、`locator`、`page`。存在正式原文行时，当前 Case 接口返回 `document_id` 和 `line_id`。读取方还需要可核验的文档版本。用户填写可以独立构成有效依据，文档和行字段允许为空。旧记录保留已有 ID 和原文行引用，来源不明时保留未知。

| 场景 | 逐条读取与展示的验收条件 |
|---|---|
| 旧 Case 的通知依据仍指向原文行 | 用原 Evidence ID 打开原文档的同一行，可核对原句与版本。 |
| 任务甲、乙分别获准使用同一原件 | 两个任务各有自己的 Evidence ID。乙引用自己的依据可读，换成甲的 ID 只显示“依据待核对”，不返回甲的内容。 |
| 任务甲的依据仍有效，关联原件已丢失 | 显示获准读取的原句，并标明“原件不可用”。 |
| 来源已失效，仍有获准读取的历史摘录 | 显示摘录，并标明“历史摘录，来源待核对”。 |
| 依据来自用户填写，创建时就没有原件 | 显示填写内容，文档和行可为空，不提示“原件丢失”。 |
| 引用无效 | 显示「依据待核对」。归属不符时隐藏被引用对象的内容。 |
| 暂时无法核验 | 标明暂时无法核验及原因。读取权限尚未确认时隐藏正文。 |

一项任务有多条依据时逐条展示各自结果。任务说明或材料名称不能代替缺失的原句。`preview_available` 仅表示格式支持预览；依据能否核验、原件能否读取需要分别判断。

## 迁移和材料边界

C 已记录 RF-015 的候选集合、版本、来源快照与结果映射草案，建议复用已有 Case Evidence。候选侧的基础增量可以独立评审。旧 Case 的资源读取、任务状态 PATCH 和材料归属继续作为 RF-038/039 的兼容入口。[C 侧迁移评审](https://github.com/Hanxx1/RuleFlow/pull/31)

Vault 已支持按任务 ID 读取关联文件。给独立任务新挂材料还涉及服务端关联校验和材料库选任务入口，两处在该基线均依赖 Case。共享原件的兼容条件是，解绑材料或删除一个任务后，其他已授权任务仍能打开原来的 Document/Vault 原件。

现有 v18 合成库回归已验证两种反例：已完成任务从 done 回退到 todo，以及材料总数不变但被转挂到同账户另一任务。正式升级验收沿用同一份迁移前快照，按原 ID 对照账户、Case、Evidence、Document 原文行、任务状态、材料所属任务、日程关联和文件摘要，再执行上表中的读取场景。已有结果覆盖合成旧库基线；正式迁移、新页面和共享原件解绑仍需在对应实现上验证。[旧任务关联回归](https://github.com/Hanxx1/RuleFlow/pull/32)
