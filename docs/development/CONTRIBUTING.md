# 四人协作约定

优先级：功能与体验稳定 > 可运行 > 职责与开发效率 > 目录形式。

| 首要负责人 | 范围 | 必须交叉评审 |
|---|---|---|
| 客户端 | features、视图、Pinia | 账户切换、资料读写、上传确认 |
| 服务端 | API、SQLite、材料/知识管理 | owner_id、事务、迁移、API 兼容 |
| 解析/AI/规则 | parsing、ai、rules、shared | EvidenceRef、UNKNOWN、模型输出校验 |
| 平台/质量 | 原生工程、脚本、CI、文档 | 分享协议、签名与构建产物 |

短期分支 + 小 PR；不要按人员建立永久隔离分支。一个提交对应一个可理解的结果，纯移动、格式化、业务修复分开。不要回填旧开发历史、伪造作者或为凑数量创建空提交。遵守 AGENTS.md。

PR 必须说明：问题、实际改动、验证命令及结果、未验证的平台、接口/UI 差异、回退点。现有缺陷单独记录，不在重构里隐式改变。失败测试先定位，不能删断言或跳过测试来获得通过。

仓库根 README 是当前运行入口。目录定位使用文件自身位置/项目配置，不写个人盘符；工具缓存允许采用系统默认。不提交数据库、上传文件、日志、密钥、截图中的私密资料、node_modules 或虚拟环境。

当前不要求统一重写所有服务、拆分 CSS、修改数据库生命周期或清理疑似无用依赖。新功能在独立任务中实现。发布/公开仓库前再次审核当前内容和所有新提交的敏感信息及素材授权。
