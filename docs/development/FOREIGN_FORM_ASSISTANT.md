# 陌生 Office 表单智能填写

本次在 5478b83 的长文核对和写回基础上，将模型辅助接入两条现有入口。使用已保存的批次时，从来源页打开「按已保存通知填表」。本机导入同样可使用，调用模型前需要登录。

## 操作流程

1. 选定通知及需要由申请人填写的表，核对适用要求。竞赛通知仍提供日程入口，也可以显式选择填写报名附件。
2. 对照原件确认位置。具有明确空白目标的陌生标签可直接在映射页选择位置，原件保护区继续在人工检查区显示。
3. 在编辑器打开「智能填写整份表单」。勾选适用的已确认画像、经历、当前普通字段或相关 TXT／DOCX 材料摘录。核对发送预览并同意。
4. 选择分析整表，查看每个字段的含义、策略、要求和共用问题。事实充足也可以直接生成整表候选。补充后重新核对本次会发送的文本。
5. 核对原文与事实，采用单个字段的要求，或批量带入所选候选。已经填写的值默认锁定；选择重做某字段并确认替换可单独更新它。手工编辑后该值的生成标记会清除，已采用的字段要求继续应用。
6. 在现有预览确认文件名、内容、原表位置与人工处理项，下载副本。已保存通知在导出前还会复核原件、通知文本及有关画像和经历。

## 数据流与约束

- 浏览器使用原始标签、位置提示、相邻格文本、通知行号及用户选定的资料。Office 原件在设备上读取，用户确认的物理映射继续约束写回。服务端接口没有原件写入、数据库写入、账户资料读取或调用模型工具的入口。
- `POST /api/v1/form-assistant` 要求登录和本次同意，复用现有 OpenAI-compatible 供应商配置。每批最多 12 个字段、120 个证据片段和约 42,000 个输入字符，超限提示缩短资料。长通知与材料以界面实际预览的摘录为准。字段很少也仍使用同一个整表接口。跨批次共享授权事实，并合并重复问题。
- 结构化响应包括字段含义、预期内容、类型、填写角色、必填状态、适用条件、策略、歧义、候选和逐字证据。短引必须出现在本次发送的指定资料中。分析没有写入动作。直接读取与提取的值必须是相关事实原句中的文字。模型可以建议用多份资料组织叙述，但引用核对与部分数字检查只能降低编造风险，用户仍需审阅事实和语义。
- 模型输出经过严格 Schema、字段集合、证据来源及引用校验。没有证据、属于他人、权限不明确、位置不安全或当前值锁定的字段无法自动带入。原表及通知中的文字按不可信数据处理。服务端不返回包含提交原文的校验错误。
- 本机继续校验必填、原表选项、日期和数值、长度及冲突。模型报告的字数上限不能覆盖可程序识别的原文下限。确定性推导支持日期差、包含起止日的天数、整数加总及计数，不执行模型提供的公式或代码。不可判定的条件、复杂格式和含义需要核对。
- 本机验收确认的是写入位置和内容回读。原件的已有内容、签审区和其他单元格不会因模型响应而写入。打印和版面容量仍以 Office 原件预览为准。
- 已保存通知可以保存七天内可恢复的原件位置和现有白名单手填值。模型候选、长文、问答和资料引用仅在当前页面使用，换通知或事项时原来的 AI 内容不会当作手填值复用。同一设备恢复后可重新选择资料分析。主动退出仍按 RF-012 清理本机草稿。
- PDF、扫描件和 XLS 不在整表模型写回范围。当前材料选择支持已确认的本机画像、经历、普通字段及用户选定的 TXT／DOCX 摘录。整个材料库自动检索、重复明细、任意控件和复杂跨字段条件待扩展。

OpenAPI 本次仅增加 POST /api/v1/form-assistant 及其三个请求结构。移除新增项后与主线契约逐项一致。接口与字段结构随本 PR 供交叉评审。

## 真实模型浏览器与文件回读

在 B 本地功能分支，用回环地址的隔离后端、合成社会实践资料和两份陌生表单复跑。Edge 完成登录、导入、确认位置、授权发送、资料不足时分析提问、补资料并生成、确认带入和下载。后端调用 DeepSeek 官方 deepseek-flash，浏览器未拦截接口响应。Word、Excel 两次分析及两次生成均返回 HTTP 200。
