# 有绪 CampusWeave · B 智能填表实施方案

## 目标与范围

学生导入一次真实通知和一组附件，在同一处查看每份表的要求和填写状态。系统带入可用资料，生成最短补录表，允许中断续填，最后导出学校可用的原格式文件，并列出打印、贴照、签章或另附证明等后续动作。竞赛报名和材料报送引导到日程。奖学金、评优中提及竞赛获奖，仍留在填表流程。

现有 11 个已核验模板保留为离线回归集。阶段完成以可复验的用户流程和格式验收为准。B 负责填表和个人资料，A 负责集成与设备验收协调，已保存导入来源、Case 和 Evidence 由 C 的现有契约提供。

## 分阶段实施与验收

| 阶段 | 子功能和改动边界 | 每项验收 |
| --- | --- | --- |
| 1A 本机来源和附件 | RF-028 / RF-032。使用导入页内存文件和正文。预检识别已知原表；从已选文件指定 DOCX 或 TXT 通知；列出其余附件，支持确认用途。通知、填写表、证明、须知和校方填写分开。 | 正常导入页选一次 DOCX 通知和原表即可继续。多份候选通知可选择。未知附件保留并显示原因。离线全过程无上传。 |
| 1B 多表及要求 | RF-028 / RF-032。要求按来源行和具体附件处理；可确定的目标直接建议，未明确时由用户逐条确认。支持有把握的下划线、连字符等命名模板；字体、打印、邮件或压缩包等未执行动作单独列出。按附件保留本次填写值。 | 同一通知与两份真实原表，两份分别填写和导出。只有一份规则有冲突时另一份可继续。切换附件后手工值保留，不带入另一表。奖学金提及竞赛不误提示，实际赛事提供日程入口。 |
| 1C 已保存来源接入 | 与 C 确认 owner、Document 原件读取、通知行和附件类别版本，从导入批次或 Case 打开同一填表工作区。扩展应先复用现有授权读取，缺失引用时解释原因。 | 使用两个隔离测试账号验证同 owner 打开、跨 owner 拒绝、原件缺失可恢复；无需重复上传。 |
| 2A 资料与经历 | RF-012 定稿后推进 RF-025 / RF-026，再增量接 RF-027。复用 Workspace v2 所在本机工作区，数据按 owner 和适用范围读取。经授权的知识库／材料库只提供事实候选，用户确认后才入档。 | 空资料只补当前缺项。跨校、跨学期、过期和相互冲突的资料分别测试。新增、编辑、删除经历后，旧导出快照仍可追溯。 |
| 2B 草稿与理由 | RF-030 / RF-031。按附件保存有版本的草稿，明确仅本次与保存供复用；证件号、联系方式、照片默认仅本次。理由支持通用草稿、按选择引用事实、手改与生成版本分开。 | 刷新续填、并发编辑冲突、账号切换、原表替换与删除逐项验证。理由长度按原表校验，事实有来源，生成失败仍可手填。 |
| 3A 陌生原表定位 | RF-029 / RF-033 / RF-034。已知版本走固定映射，陌生 DOCX／XLSX 按标签、角色、类型、局部结构和限制提位置候选。必要时用公共 AI 提议，用户核对后程序才允许写入。 | 用各一份此前未内置的真实 DOCX 和 XLSX 验收。申请人、辅导员同名字段正确区分。未知保护区、同名异版或解析失败保留原件和可复制填写清单。 |
| 3B 文件核对及设备交付 | RF-033 / RF-034 / RF-035 / RF-007 文件子项。分开显示字段值、版式预检和人工动作。冻结确认值，原格式写回后复读并校验保护区；Android 保存、打开、分享单独验收。 | 验证字体、长文溢出、分页、公式及合并区、前导零、电子照片和纸质贴照、命名、重试及离线。WPS／Office 和真机记录各自实测范围。XLS、可填写 PDF、扫描表单另按 RF-036 / RF-037 分类型。 |

## 交互和实现边界

- 附件状态至少区分待确认、可填写、需核对要求、填写中、已导出。未解析的通知要求显示原文和「待人工核对」。签审、证明和线下交件以提醒呈现。
- 第一阶段先在 `NoticeIntake.vue` 和 `FormDemoView.vue` 实现独立附件工作流。通知和附件保存在当前页面会话；同批切换保留填写值并撤销旧导出确认。证据使用本次来源名及原行号，账户持久层接入时复用 EvidenceRef。现有导出器的原件指纹与保护区保持约束。
- 正式草稿建议以 owner、可空 case_id、原件 ID 与 hash、映射版本、规则版本、revision、已确认字段及其来源、输出文件名和确认快照标识。经历和原件保留版本引用。导出失败可重试同一快照。附件变更只使受影响表格待复核。
- 资料和未导出文件默认本机处理。需要服务端或外部模型时，按用途限制数据范围，经 Privacy Guard 和用户确认后才发送。退出清理、备份、敏感字段持久化及旧版兼容交由 RF-012 协调。与 C 对齐 FileRef、Evidence 作用域和原件删除保护。公共 API、数据库和原生配置变更进入团队评审。
- 对于纸质贴照，保持照片槽和原说明，导出后提醒。电子照仅在通知或模板明确允许时启用。只清理允许写入格内的占位说明。已生成文件与学校收件分别显示。
- 通过第一阶段后，以「真实通知、两份申请表和一份证明」跑完整链。用合成个人资料验收，真实私人文件不进入 Git。每阶段运行相应单测、浏览器端到端和离线回归，按 B 工作记录登记命令、结果、限制和实际文件证据。功能分支本地开发，提交评审前不创建 PR 或推送主线。

## 当前实施状态

- 1A、1B 本机切片已在 RF-028 分支验证。组合测试使用合成通知及证明角色样本，搭配两份真实校方空白原表；另有南科大公开通知与原表的单表链路。正式同一通知的真实多附件仍待补充为验收样本。
- 1C 已走读。已有按 owner 授权的 Document 元数据、原件与行读取接口，导入批次的文件来源可带 `metadata.document_id`。旧粘贴正文没有该引用，批次 DTO 不暴露正文。与 C 对齐批次／Case 可用正文、附件来源版本、失败和解绑语义后接入。
- 2A、2B 的正式保存边界待 RF-012 团队确认。3A、3B 仍待实施与相应格式、设备验收。详见 [B 开发记录](records/B_form_filling.md#rf-028从导入通知到原件填写与导出)。
