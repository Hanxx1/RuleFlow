# 有绪 CampusWeave · B 智能填表实施方案

## 目标与范围

学生导入一次真实通知和一组附件，在同一处查看每份表的要求和填写状态。系统带入可用资料，生成最短补录表，允许中断续填，最后导出可编辑的原格式文件，显示打印、贴照、签章及另附证明等办理要求，由用户按通知自行提交。竞赛报名和材料报送引导到日程。奖学金、评优中提及竞赛获奖，仍留在填表流程。

现有 11 个已核验模板保留为离线回归集。阶段完成以可复验的用户流程和格式验收为准。B 负责填表和个人资料，A 负责集成与设备验收协调，已保存导入来源、Case 和 Evidence 由 C 的现有契约提供。

## 分阶段实施与验收

| 阶段 | 子功能和改动边界 | 每项验收 |
| --- | --- | --- |
| 1A 本机来源和附件 | RF-028 / RF-032。使用导入页内存文件和正文。预检识别已知原表；从已选文件指定 DOCX 或 TXT 通知；列出其余附件，支持确认用途。通知、填写表、证明、须知和校方填写分开。 | 正常导入页选一次 DOCX 通知和原表即可继续。多份候选通知可选择。未知附件保留并显示原因。离线全过程无上传。 |
| 1B 多表及要求 | RF-028 / RF-032。要求按来源行和具体附件处理；可确定的目标直接建议，未明确时由用户逐条确认。支持有把握的下划线、连字符等命名模板；字体、打印、邮件或压缩包等未执行动作单独列出。按附件保留本次填写值。 | 同一通知与两份真实原表，两份分别填写和导出。只有一份规则有冲突时另一份可继续。切换附件后手工值保留，不带入另一表。奖学金提及竞赛不误提示，实际赛事提供日程入口。 |
| 1C-a 读取已保存来源 | 从批次来源页进入同一填表编辑器。复用 C 的 `readFormContext` 和鉴权原件读取。下载原件后按实际字节校验 SHA-256，原件和解析状态分别处理。 | 同账户能打开，跨账户和非法引用拒绝。文件名和大小相同但字节变化时暂停该表。 |
| 1C-b 按表保留和绑定要求 | 以批次、来源和原件版本标识当前页面草稿。适用范围按来源 ID 保存。旧正文无正式行时显示待核对。移除、补充原件沿用现有批次写入和隐私确认。 | 重排和切换保留原值。只更换 A 时 B 保留。重传产生新来源时，旧稿仅用于对照，用户逐项选值带入。 |
| 1C-c 导出前复核 | 导出前重读表、适用通知和原件，下载后校验字节，再复核来源关系。父来源缺失时允许继续填写。关键要求无法核对时暂停确认导出。 | 同 revision 的变化可检测。A 的适用条款变化影响 A。B 可继续使用已复核的要求。父来源缺失后，用户明确确认另一份有效通知才恢复导出。 |
| 2A-a 画像带入 | RF-025。只读当前账号的 Workspace，按模板校别、事项范围和有效期筛选已确认资料。用户预览并选择带入空项，导出前复核带入的依据。 | 手填值保留。跨校、跨事项、过期、冲突或不符原表格式的值跳过。核对期间资料变化需要重新确认。|
| 2A-b 正式资料与经历 | RF-026 首个切片支持账户本机手工新增、核对和按记录版本保存，以及奖学金原表的获奖组带入。Workspace 与备份合并按 RF-012 协调，RF-027 再接经授权的资料候选。 | 核对账号隔离、待确认经历跳过、奖项写入空行、改删经历后需重新核对。已下载的文件保留原值，长期快照另验。 |
| 2B-a 申请理由 | RF-030 本机起草先行。奖学金可用通用稿或引用用户选中的已确认奖项，需具体事由的表格以用户输入为基础。生成、接受和手改各有状态，公共模型能力另行对接。 | 通知和原表字数同时生效，所选事实可复核。重新起草只更新预览，导出使用最终填写值。 |
| 2B-b 草稿与快照 | RF-031。同一标签页按账号、原件及版本显式保存草稿。理由单独授权保存；导出使用用户确认时冻结的内容。 | 刷新续填、保存版本冲突、标签页与账号隔离、改版仅供对照。导出必须重新确认。 |
| 3A 陌生原表定位 | RF-029 / RF-033 / RF-034。两个通知填写入口复用同一套本机规则来识别陌生 DOCX／XLSX 的位置，用户确认映射才允许写入。 | 用各一份此前未内置的真实 DOCX 和 XLSX 验收。申请人、辅导员同名字段正确区分。位置不明或重叠时保留页面填写清单；受保护或解析失败的文件保留原件。 |
| 3B-a 本机文件交付 | RF-033 / RF-034 / RF-035。分开展示填写值、排版限制、通知版式原文和人工动作。按确认快照校验生成文件，同一确认可重复下载，每次重新核对来源。 | 测试重试、格式和命名、改版拦截、DOCX/XLSX 在 Word、Excel 和 WPS 打开及二次编辑。打印验证分表记录。 |
| 3B-b 材料库存档与设备交付 | RF-035 复用现有材料库的上传与授权下载，主动同意后保存当前确认件，可选关联该通知的 Case。独立导出历史和服务端幂等另按共享契约评审。RF-007 文件子项在 Android 真机验证。 | 验证显式同意、有或无事项、账号隔离、重复提交和回执丢失。记录原生设备环境、取消、失败与重试。XLS、可填写 PDF、扫描表单另按 RF-036 / RF-037 分类型。 |

## 交互和实现边界

- 附件状态至少区分待确认、可填写、需核对要求、填写中、已导出。未解析的通知要求显示原文和「待人工核对」。签审、证明和线下交件以提醒呈现。
- 第一阶段先在 `NoticeIntake.vue` 和 `FormDemoView.vue` 实现独立附件工作流。通知和附件保存在当前页面会话；同批切换保留填写值并撤销旧导出确认。证据使用本次来源名及原行号，账户持久层接入时复用 EvidenceRef。现有导出器的原件指纹与保护区保持约束。
- 正式草稿建议以 owner、可空 case_id、原件 ID 与 hash、映射版本、规则版本、revision、已确认字段及其来源、输出文件名和确认快照标识。经历和原件保留版本引用。导出失败可重试同一快照。附件变更只使受影响表格待复核。
- 资料和未导出文件默认本机处理。需要服务端或外部模型时，按用途限制数据范围，经 Privacy Guard 和用户确认后才发送。退出清理、备份、敏感字段持久化及旧版兼容交由 RF-012 协调。与 C 对齐 FileRef、Evidence 作用域和原件删除保护。公共 API、数据库和原生配置变更进入团队评审。
- 对于纸质贴照，保持照片槽和原说明，导出后提醒。电子照仅在通知或模板明确允许时启用。只清理允许写入格内的占位说明。已生成文件与学校收件分别显示。
- 通过第一阶段后，以「真实通知、两份申请表和一份证明」跑完整链。用合成个人资料验收，真实私人文件不进入 Git。每阶段运行相应单测、浏览器端到端和离线回归，按 B 工作记录登记命令、结果、限制和实际文件证据。功能分支本地开发，提交评审前不创建 PR 或推送主线。

## 当前实施状态

- 1A、1B 本机切片已在 RF-028 分支验证。组合测试使用合成通知及证明角色样本，搭配两份真实校方空白原表；另有南科大公开通知与原表的单表链路。同一真实通知的多附件样本见下方已保存入口的验收。
- 1C 基于 C 已合入的 [HTTP 接口](https://github.com/Hanxx1/RuleFlow/pull/38)和[类型化客户端](https://github.com/Hanxx1/RuleFlow/pull/39)。入口为已保存批次的来源页。原件复核使用记录的文档版本和 SHA-256，普通文件错误按表处理，非法来源关系暂停批次读取。展现保留真实原文行，旧粘贴文本独立标记。
- 1C 的自动化验收分为 `savedNotice.test.ts` 的规则和身份测试、C 侧来源接口回归、`scripts/test-saved-notice-form-browser.cjs` 的实际登录与双表流程。浏览器测试使用隔离后端和合成账户。既有回归使用合成通知和两份校方真实空白表。新增验收使用西北大学同一历史通知的两张原表和返校证明模板，已通过实际登录、原格式下载、分区与换表草稿隔离。整页 HTML 提取有待核对，本次使用同页真实正文 TXT。
- 1C 现已接入 C 的共享原件校验。进入填写和导出都核验下载字节及原件关系，填表侧继续在前后核对适用通知、逐表要求及草稿身份。浏览器通过传输期间通知变更、原件同尺寸变化、换一表保另一表、父来源缺失的回归。
- 2A-a 已验证已保存通知的画像带入。可用范围为已核验模板中的院系、专业、班级及兼容的学生类型。带入后可核对其本机画像依据，导出前复核当前值和依据。画像来源型数据保留在当前会话，续填时重读。跨校、旧学籍证明和无有效依据的值留给用户处理。
- 2A-b 手工经历使用账户分区的本机档案，记录保留用户确认来源与版本，退出账号时按当前本机资料规则清除。现有 Workspace 备份不包含经历。获奖组按当前已核验奖学金表的年月、字段长度和空行检查；更换模板时重新从档案核对，当前会话内保留原带入值供对照。
- 2B-a 本机起草已验证已保存通知的奖学金 XLSX 和学生证补办 DOCX。已采用稿、引用依据与手改最终值按附件保留，可由用户选择随草稿保存。外部模型及 Privacy Guard 接入待共同确认。
- 2B-b 标签页草稿可选保存当前理由、采用的本机稿和选中依据。刷新后须由同一账号重新登录并核验对应原件；理由的引用在导出前复核。换版后的旧理由只供对照。草稿保存拒绝旧版本写入，冲突时由用户明确选择读取已保存版。确认快照只在页面内有效，登出清除本标签页该账号的草稿。长期保存、跨标签页同步、备份和历史导出按 RF-012／RF-031 后续验证。
- RF-012 已在隔离浏览器技术样例中验证同账号关页恢复、按传入 owner 划分的本机分区、服务端原件鉴权、跨标签页事务冲突、同名重传和清理后的旧写入。本机读取与登录会话的绑定、退出清理范围、保留期限和备份边界留待正式存储评审。
- 3A 已接入本机导入和已保存通知。陌生原表使用本机字段匹配，复核后写回并复读；再次选择不同的写入位置时保留各自的页面填写值。已验证两份公开校方原表及歧义、保护、贴照等合成回归。陌生表的画像复用和刷新续填仍待后续验收。
